# 歷史模式：丟一個題目，產出 10–15 分鐘 MP4

## 怎麼用

方法一（建議）：到 [Actions → One Topic History Video](https://github.com/Beetheone/free-ai-video-generator/actions/workflows/one-topic-history.yml) → Run workflow，輸入題目（例如「澳洲大戰鴕鳥」）、選分鐘數（10–15）、按執行。

方法二（排隊）：把 1–3 個題目寫進 `config/history-topics.json`（JSON 陣列）並推送，會自動開始。做完請把檔案清回 `[]`，避免重複製作。

完成後到該次執行的 **Artifacts** 下載：

| 檔案 | 用途 |
| --- | --- |
| `documentary.mp4` | 1080p 成品 |
| `documentary.srt` | 字幕檔（畫面上已燒錄字幕） |
| `thumbnail.jpg` | 縮圖 |
| `DESCRIPTION.txt` | YouTube 說明欄：簡介、章節時間、資料來源、圖片與音樂授權、AI 揭露 |
| `ATTRIBUTION.md`、`sources.json` | 每張圖片、音樂的來源與授權 |
| `PROGRESS.md`、`qa_report.json` | 每一步做到哪裡、為何停止 |

## 流程

1. 中英文查詢與圖片查詢 → 讀取來源本文 → 逐字引句與跨來源審核（沿用既有流程）。
2. 腳本採「勾人結構」：開場三個場景先講最反直覺的結局並丟出問題；每一章結尾留懸念；有爭議的說法必須標明。開場另有自動審核，結果記在 `hook_audit.json`（僅提示，不會因此丟棄腳本）。
3. 畫面：只用 Wikimedia Commons 中明確標示公有領域、CC0、CC BY 的圖片。每張都由視覺模型看過實際內容，排除血腥、浮水印與無關圖片，再對應到每段旁白。以 Ken Burns 運鏡（拉近、拉遠、左右平移）製作，保留日期標籤與字幕。
4. 配音：預設 Edge 台灣中文；連不上時自動改用 Kokoro 普通話。
5. 背景音樂：自動找一首授權的純音樂，說話時自動壓低；找不到就不放，不會因此失敗。
6. 輸出前檢查：長度、音畫同步、字幕時間、黑畫面、靜音；任何一項不過就不釋出影片。
7. 標題、縮圖文字、說明欄由模型根據已查證的主張產生，並再審一次是否誇大；審核不過就退回題目原文。

## 上傳 YouTube（選用）

流程會把影片以**私人**上傳，並自動勾選「變更或合成內容」揭露；你在 YouTube Studio 看過後自己按公開。需要先在 GitHub 倉庫設定三個 Secrets：`YT_CLIENT_ID`、`YT_CLIENT_SECRET`、`YT_REFRESH_TOKEN`（Google Cloud 建立 OAuth 用戶端、授權範圍 `youtube.upload`）。執行時把 `upload` 選為 `private`。

注意：尚未通過 Google 審核的 API 專案，上傳的影片會被強制為私人，這正好符合這裡的設計，但你必須自己公開。自訂縮圖需要頻道已完成電話驗證，否則影片會上傳成功、縮圖需手動設定。

## 限制（請先知道）

- 題目要有足夠可查的文字資料，且 Commons 上要有足夠的授權圖片（至少 8 張相關圖片）。冷門題目會明確失敗並說明原因，不會用無關圖片或文字卡補位。
- 圖片以老照片、畫作、地圖為主，運鏡讓它動起來，但它仍是靜態史料，不是影片素材。部分圖片是同時代、同主題的資料圖，未必拍攝於事件當下，說明欄已據實揭露。
- 自動審核不能保證事實或授權正確。上傳公開前請至少看一遍開場與標題。
- 旁白自然度尚未經人耳驗收；Edge 台灣中文通常比 Kokoro 自然。
- 一次製作會呼叫模型約 100–200 次，Gemini 免費額度可能不夠一天做很多支。可用 `LLM_MAX_CALLS`、`LLM_MIN_INTERVAL` 調整。
- 能否加入 YouTube 合作夥伴計畫，取決於訂閱數、觀看時數與內容是否有原創價值；全自動大量製作且缺乏個人觀點的頻道有被判為「不真實內容」的風險。建議固定一個系列、在腳本審稿時加入你自己的觀點。
